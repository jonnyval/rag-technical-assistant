# RegLab RAG System

Продвинутая система Retrieval-Augmented Generation (RAG) для интеллектуального поиска по технической документации (Astra.IDE, R500, AstraRegul) и базе обращений технической поддержки. 

Проект построен на базе архитектуры LangChain и поддерживает гибридный поиск, передовые методы чанкинга и гибкое переключение между облачными и локальными LLM.

## 🛠 Ключевые особенности
* **Гибридный поиск:** Комбинация плотных векторов (Dense) и лексического поиска (BM25) с последующим реранжированием через Cross-Encoder.
* **Parent-Child Chunking:** Для векторного поиска используются мелкие чанки, а в контекст LLM передаются полные родительские документы для сохранения семантики.
* **Hypothetical Document Embeddings (HyDE):** Опциональная генерация гипотетических ответов перед поиском для улучшения семантического соответствия.
* **Умный парсинг и метаданные:** Извлечение таблиц в Markdown из DOCX/HTML, автоматическая генерация потенциальных вопросов и ключевых слов с помощью локальных LLM (Ollama/DeepSeek).
* **Обработка тикетов (SGR):** Извлечение фактов из JSON/HTML-тикетов с жесткой фильтрацией персональных данных (PII) и суммаризацией «симптом-решение».
* **Поддержка Qdrant и ChromaDB:** Основной упор сделан на Qdrant (через Docker), но сохранена обратная совместимость с ChromaDB.

## 📁 Структура проекта
* `src/` — ядро проекта (настройки, логгер).
* `src/document_processing/` — парсеры документов, чистка данных, векторизация.
* `src/retrieval/` — кастомные ретриверы, BM25, HyDE, логика поиска.
* `src/utils/` — вспомогательные скрипты для профилирования и диагностики БД.
* `scripts/` — точки входа, UI на Streamlit.
* `data/` — (в `.gitignore`) исходные документы, векторные БД, кэш BM25, логи.

## ⚙️ Настройка
Все основные параметры (выбор LLM, пороги реранжирования, настройки чанкинга, пути к БД) задаются в файле `config.yaml`. Конфиденциальные ключи (API) загружаются из `.env`. Запуск Qdrant осуществляется через `docker-compose.yml`.

# 📚 RAG Technical Assistant (RegLab)

Интеллектуальная система на базе архитектуры RAG (Retrieval-Augmented Generation) для поиска и ответов на вопросы по технической документации ПЛК (Regul R500, R500S, AstraRegul).

## ✨ Ключевые особенности

* **Гибридный поиск (Hybrid Search):** Комбинация векторного поиска (Dense) и лексического алгоритма BM25 (Sparse) для точного нахождения терминов.
* **Стратегия Parent-Child Chunking:** Документы разбиваются на мелкие фрагменты (400 символов) для точного поиска, но в LLM передается полный контекст родительского абзаца или раздела.
* **Умные метаданные:** Использование локальных LLM (через Ollama) для автоматического извлечения тегов и описаний документов на этапе загрузки (Ingest).
* **Реранжирование:** Интеграция моделей BGE-Reranker для переупорядочивания результатов и повышения релевантности контекста.
* **Поддержка множества LLM:** Гибкое переключение между Ollama (Qwen3), Gemini, GigaChat и Groq.

## 🛠 Технологический стек

* **Оркестрация:** LangChain (Core, Community, OpenAI-compatible).
* **Векторные БД:** Qdrant (в Docker) и ChromaDB.
* **Embeddings:** HuggingFace (`BGE-M3`, `Qwen3-Embedding`).
* **Парсинг:** `mammoth` (DOCX с сохранением стилей), `beautifulsoup4` (HTML).
* **Интерфейс:** Streamlit.
* **Локальные модели:** Ollama.

## 📁 Структура проекта

* `src/` — Ядро системы:
    * `document_processing/` — Логика парсинга документов и извлечения метаданных.
    * `retrieval/` — Реализация гибридного поиска и логики RAG.
* `scripts/` — Рабочие скрипты:
    * `run_ingest_qdrant_v2.py` — Индексация документов в Qdrant.
    * `app_qdrant v2.py` — Основной UI на Streamlit.
    * `build_bm25.py` — Сборка кэша для лексического поиска.
    * `run_evaluator.py` — Оценка качества работы системы.
* `config.yaml` — Единый файл конфигурации всех моделей и путей.
* `docker-compose.yml` — Окружение для запуска Qdrant.

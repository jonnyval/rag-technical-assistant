# `src`

Папка содержит основной код RAG-системы. Здесь находится конфигурация, движок ответа, логирование, обработка исходных документов и retriever-ы.

## Файлы верхнего уровня

- `config.py` - читает `config.yaml` и `.env`, собирает пути, параметры моделей, Qdrant, chunking, rerank и LLM-провайдеров.
- `config_validator.py` - проверяет корректность конфигурации и наличие критичных параметров.
- `engine.py` - главный `RAGEngine`: инициализация embeddings, Qdrant, reranker, LLM и orchestration ответа.
- `module_detection.py` - определяет модули по `data/module_alias_taxonomy.json`, нормализует алиасы вроде `CU00821`, расширяет retrieval-запрос, добавляет подсказки для точного добора разделов документации и ранжирует тикеты по модульным метаданным.
- `context_formatting.py` - форматирует документы и тикеты для LLM, строит `SourceReference`, проставляет стабильные ID источников прямо в заголовки контекстных фрагментов.
- `evidence_guard.py` - содержит post-guards против неподтвержденных выводов, в том числе строгий режим для вопросов "что означает/что это/расшифруй" по буквам, суффиксам и маркировкам.
- `logger.py` - централизованное логирование приложения и аудит запросов.

## Подпапки

- `document_processing/` - парсеры документации и тикетов, переиндексация и подготовка данных.
- `retrieval/` - retriever-ы для Qdrant, dual-search и вспомогательная логика поиска.
- `utils/` - диагностические и сервисные инструменты.

## Важное

`engine.py` является точкой сборки production-пайплайна. Детерминированные правила лучше добавлять в специализированные модули:

- новые алиасы и правила поиска модулей - в `module_detection.py`;
- изменение вида контекста и источников - в `context_formatting.py`;
- защита от неподтвержденных формулировок и post-processing ответа - в `evidence_guard.py`.

При изменении индексации или формата метаданных нужно проверять совместимость с `DualRetriever`, форматированием источников и API-ответами.

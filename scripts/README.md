# Скрипты и точки входа (Scripts)

В данной директории собраны исполняемые скрипты проекта. Они охватывают весь жизненный цикл RAG-системы: от сбора данных (скрейпинга) и их векторизации до пользовательского интерфейса, автоматического тестирования и оценки качества (Evaluation).

## 🗂 Структура директории

Скрипты логически разделены на несколько категорий:

### 🖥 1. Веб-интерфейс (User Interface)
* **`app_qdrant.py`** — основное веб-приложение на базе **Streamlit**. 
  * Инициализирует пайплайн гибридного поиска (Qdrant + BM25) с реранжированием (CrossEncoder).
  * Реализует паттерн **Schema-Guided Reasoning (SGR)**: заставляет LLM жестко следовать JSON-схеме (интент, извлеченные факты, чего не хватает, финальный ответ).
  * Включает умную маршрутизацию/фильтрацию по оборудованию (AstraRegul, R500, R500S) на основе регулярных выражений или ручного выбора пользователя.
  * Поддерживает ротацию API-ключей и работу с различными моделями (Groq, Gemini, GigaChat, Ollama).
  * Умеет выводить релевантные изображения из документации прямо в чат.

### 📥 2. Сбор и индексация данных (Data Ingestion)
* **`download_tickets_json.py`** — парсер/скрейпер обращений техподдержки с портала `support.prosyst.ru`.
  * Работает через внутреннее API портала с использованием авторизационных куки.
  * Фильтрует тикеты по ключевым словам и статусам.
  * **Анонимизирует данные:** заменяет реальные имена на теги `[КЛИЕНТ]` и `[ИНЖЕНЕР]`.
  * Расшифровывает внутренние коды оборудования и категорий в читаемый текст.
* **`run_ingest_qdrant.py`** — главный пайплайн векторизации данных.
  * Считывает DOCX, HTML и JSON-тикеты.
  * Реализует защиту от дубликатов с помощью MD5-хеширования (реестр хэшей `hash_registry.json`).
  * Использует `ParentDocumentRetriever`: нарезает документы на мелкие `child` чанки для точного поиска, сохраняя большие `parent` фрагменты в SQLite для контекста LLM.
  * Поддерживает батчевую (пакетную) загрузку в Qdrant с автоматической очисткой памяти GPU (`gc.collect`, `torch.cuda.empty_cache`).

### 🧪 3. Автоматическое тестирование (Auto-testing)
Скрипты для прогона наборов вопросов (Ground Truth) без ручного участия.
* **`run_autotest_qdrant.py`** — базовый скрипт автотестирования. Прогоняет JSON-файлы с вопросами через пайплайн, сохраняет ответы LLM, ее «мышление» (SGR Audit) и извлеченные факты.
* **`run_autotest_qdrant_hyde.py`** — продвинутая версия автотестов с **адаптивным HyDE**. 
  * Включает эвристику на базе регулярных выражений: если вопрос требует точного поиска по таблице (lookup: *значения индикаторов, конкретные коды, пути*), HyDE динамически отключается, чтобы модель не «галлюцинировала» неверные коды. Для концептуальных вопросов HyDE остается включенным.

### 📊 4. Оценка качества (Evaluation)
* **`run_evaluator.py`** — умный оценщик (`UnifiedEvaluator`), использующий подход **LLM-as-a-Judge**.
  * Сравнивает ответ RAG-системы с эталонным ответом.
  * *Шаг 1:* Считает косинусное расстояние (Cosine Similarity) между эмбеддингами ответов.
  * *Шаг 2:* Если сходство ниже порога (0.82), отправляет ответы на суд LLM с температурой 0.0 (строгий судья).
  * *Шаг 3:* Генерирует детальные отчеты (JSON dumps + CSV сводку с процентом Accuracy) с добавлением таймстампов. Сохраняет отдельный лог ошибок.

### 🛠 5. Утилиты и Поиск
* **`hyde.py`** — модуль генерации гипотетических ответов (Hypothetical Document Embeddings). Содержит специализированный промпт для стиля «сухой технической документации» РегЛаб и логику fallback, если модель генерирует мусор.
* **`preview_tickets_with_llm.py`** — утилита для тестирования парсинга JSON-тикетов. Показывает превью нарезанных чанков, извлеченные метаданные (doc_level, equipment_type) и проверяет наличие тегов ролей.
* **`test_tickets_search.py`** — консольная CLI-утилита. Позволяет быстро тестировать качество поиска напрямую в коллекции Qdrant (выдает ТОП-3 чанка со score), не поднимая веб-интерфейс Streamlit и без участия LLM.
